# Offbeat --- Database Schema Design

**Status:** Phase 2.1 --- Design specification\
**Database:** Supabase PostgreSQL\
**Identity:** Supabase Auth

## 1. Purpose

This document defines Offbeat's initial data model for a music-listening
application that organizes music from external providers, supports
playlists and likes, records listening history, and plans for downloads
and offline use.

PostgreSQL stores metadata and references, not audio binaries. Provider
integrations handle their own supported playback mechanisms. IndexedDB
and Service Worker/Cache Storage provide device-local offline
capabilities.

## 2. Architecture boundaries

  -----------------------------------------------------------------------
  Component                           Responsibility
  ----------------------------------- -----------------------------------
  Supabase Auth                       Identity, passwords, and sessions

  `profiles`                          Application-specific user
                                      information

  Catalog tables                      Artists, albums, tracks, and source
                                      references

  User-data tables                    Playlists, playlist membership,
                                      likes, and listening history

  Provider adapters                   Provider-specific search, playback,
                                      and availability

  IndexedDB                           Local metadata and audio blobs for
                                      supported downloads

  Service Worker / Cache Storage      Offline app shell and static
                                      resources
  -----------------------------------------------------------------------

A provider embed does not automatically make its audio downloadable.
Offline audio must be available through a supported download mechanism
or a user-supplied file that may be stored locally.

## 3. Entity relationship overview

``` text
Supabase Auth 1 --- 1 profiles

artists 1 --- * albums
artists 1 --- * tracks
albums  1 --- * tracks (album is optional)
tracks  1 --- * track_sources

profiles 1 --- * playlists
playlists * --- * tracks through playlist_tracks
profiles  * --- * tracks through likes
profiles 1 --- * listening_history
tracks   1 --- * listening_history
```

The nine application tables are `profiles`, `artists`, `albums`,
`tracks`, `track_sources`, `playlists`, `playlist_tracks`, `likes`, and
`listening_history`. Supabase's `auth.users` table is managed by
Supabase and is not created by this schema.

## 4. Table specifications

### 4.1 `profiles`

Application-specific information for an authenticated user.

  -----------------------------------------------------------------------------
  Column           Type                          Required Rules / purpose
  ---------------- ---------------- --------------------- ---------------------
  `id`             `uuid`                             Yes Primary key;
                                                          references
                                                          `auth.users(id)` with
                                                          `ON DELETE CASCADE`

  `username`       `text`                              No Unique when present;
                                                          3--30 characters,
                                                          letters, digits,
                                                          underscores

  `display_name`   `text`                              No Display name

  `avatar_url`     `text`                              No Optional avatar
                                                          reference

  `created_at`     `timestamptz`                      Yes Defaults to `now()`
  -----------------------------------------------------------------------------

Rules: users can read and update only their own profile; they cannot
change the profile ID to impersonate another user. Authentication
credentials remain in Supabase Auth.

### 4.2 `artists`

  -----------------------------------------------------------------------------
  Column           Type                          Required Rules / purpose
  ---------------- ---------------- --------------------- ---------------------
  `id`             `uuid`                             Yes Primary key,
                                                          generated by
                                                          `gen_random_uuid()`

  `name`           `text`                             Yes Must not be empty
                                                          after trimming

  `bio`            `text`                              No Optional biography

  `image_url`      `text`                              No Optional image
                                                          reference

  `created_at`     `timestamptz`                      Yes Defaults to `now()`

  `updated_at`     `timestamptz`                      Yes Defaults to `now()`;
                                                          maintained on updates
  -----------------------------------------------------------------------------

One artist may have many albums and tracks. Artist names are not
globally unique. Catalog records are managed by a trusted catalog
workflow rather than arbitrary browser writes.

### 4.3 `albums`

  ------------------------------------------------------------------------
  Column           Type                          Required Rules / purpose
  ---------------- ---------------- --------------------- ----------------
  `id`             `uuid`                             Yes Primary key

  `artist_id`      `uuid`                             Yes Foreign key to
                                                          `artists(id)`

  `title`          `text`                             Yes Must not be
                                                          empty after
                                                          trimming

  `artwork_url`    `text`                              No Optional artwork
                                                          reference

  `release_date`   `date`                              No Optional release
                                                          date

  `created_at`     `timestamptz`                      Yes Defaults to
                                                          `now()`

  `updated_at`     `timestamptz`                      Yes Defaults to
                                                          `now()`;
                                                          maintained on
                                                          updates
  ------------------------------------------------------------------------

An album has one primary artist in the MVP. Album titles need not be
globally unique. Deletion of an artist with dependent albums should be
restricted until the relationships are handled deliberately.

### 4.4 `tracks`

Canonical track metadata, independent of a specific provider.

  ----------------------------------------------------------------------------
  Column               Type                          Required Rules / purpose
  -------------------- ---------------- --------------------- ----------------
  `id`                 `uuid`                             Yes Primary key

  `artist_id`          `uuid`                             Yes Foreign key to
                                                              `artists(id)`;
                                                              primary artist

  `album_id`           `uuid`                              No Foreign key to
                                                              `albums(id)`;
                                                              nullable for
                                                              singles

  `title`              `text`                             Yes Must not be
                                                              empty after
                                                              trimming

  `duration_seconds`   `integer`                           No If present,
                                                              greater than
                                                              zero

  `artwork_url`        `text`                              No Optional track
                                                              artwork

  `created_at`         `timestamptz`                      Yes Defaults to
                                                              `now()`

  `updated_at`         `timestamptz`                      Yes Defaults to
                                                              `now()`;
                                                              maintained on
                                                              updates
  ----------------------------------------------------------------------------

Every track has one primary artist in the MVP. Album membership is
optional. One track may have multiple provider sources. If `album_id` is
present, the album and track primary artists must match; enforce this
with a composite foreign key or equivalent database constraint.

### 4.5 `track_sources`

Associates a canonical track with one or more external playback sources.

  ---------------------------------------------------------------------------------
  Column               Type                          Required Rules / purpose
  -------------------- ---------------- --------------------- ---------------------
  `id`                 `uuid`                             Yes Primary key

  `track_id`           `uuid`                             Yes Foreign key to
                                                              `tracks(id)` with
                                                              `ON DELETE CASCADE`

  `provider`           `text`                             Yes Provider identifier,
                                                              e.g. `youtube`

  `provider_item_id`   `text`                              No Provider-specific
                                                              content ID

  `source_url`         `text`                             Yes Canonical source URL

  `playback_mode`      `text`                             Yes `embed`,
                                                              `direct_stream`, or
                                                              `external_link`

  `last_checked_at`    `timestamptz`                       No Last availability
                                                              check

  `created_at`         `timestamptz`                      Yes Defaults to `now()`
  ---------------------------------------------------------------------------------

Rules: - Constrain `playback_mode` to the supported values. - When a
stable provider ID exists, enforce uniqueness on
`(provider, provider_item_id)`. - For sources without stable IDs,
normalize URLs and deduplicate according to provider rules. - Do not
store temporary or expiring stream URLs as permanent references. -
Validate and allowlist provider hosts; do not render arbitrary
user-supplied embed HTML. - An embed does not imply permission or
technical ability to download its audio.

### 4.6 `playlists`

  -----------------------------------------------------------------------------
  Column           Type                          Required Rules / purpose
  ---------------- ---------------- --------------------- ---------------------
  `id`             `uuid`                             Yes Primary key

  `owner_id`       `uuid`                             Yes Foreign key to
                                                          `profiles(id)` with
                                                          `ON DELETE CASCADE`

  `name`           `text`                             Yes Must not be empty
                                                          after trimming

  `description`    `text`                              No Optional description

  `created_at`     `timestamptz`                      Yes Defaults to `now()`

  `updated_at`     `timestamptz`                      Yes Defaults to `now()`;
                                                          maintained on updates
  -----------------------------------------------------------------------------

Every playlist has one owner. Playlists are private in the MVP. Only the
owner may read, update, or delete their playlists. Names need not be
unique per user.

### 4.7 `playlist_tracks`

Connects playlists and tracks and stores their order.

  -----------------------------------------------------------------------------
  Column           Type                          Required Rules / purpose
  ---------------- ---------------- --------------------- ---------------------
  `playlist_id`    `uuid`                             Yes Foreign key to
                                                          `playlists(id)` with
                                                          `ON DELETE CASCADE`

  `track_id`       `uuid`                             Yes Foreign key to
                                                          `tracks(id)` with
                                                          `ON DELETE CASCADE`

  `position`       `integer`                          Yes Positive integer
                                                          specifying playback
                                                          order

  `added_at`       `timestamptz`                      Yes Defaults to `now()`
  -----------------------------------------------------------------------------

Constraints: - Composite primary key `(playlist_id, track_id)`. - Unique
`(playlist_id, position)`. - A track cannot appear twice in one playlist
under this MVP model. - A track may appear in multiple playlists. - Only
the playlist owner may add, remove, or reorder its tracks. - Reordering
logic must handle position collisions. - The mutation workflow must
verify that the referenced track is accessible to the playlist owner.

### 4.8 `likes`

  -----------------------------------------------------------------------------
  Column           Type                          Required Rules / purpose
  ---------------- ---------------- --------------------- ---------------------
  `user_id`        `uuid`                             Yes Foreign key to
                                                          `profiles(id)` with
                                                          `ON DELETE CASCADE`

  `track_id`       `uuid`                             Yes Foreign key to
                                                          `tracks(id)` with
                                                          `ON DELETE CASCADE`

  `created_at`     `timestamptz`                      Yes Defaults to `now()`
  -----------------------------------------------------------------------------

Composite primary key `(user_id, track_id)` prevents duplicate likes.
Users may read, add, and remove only their own likes.

### 4.9 `listening_history`

Records playback events. Repeated plays of the same track are expected.

  ---------------------------------------------------------------------------------
  Column               Type                          Required Rules / purpose
  -------------------- ---------------- --------------------- ---------------------
  `id`                 `bigint`                           Yes Identity primary key

  `user_id`            `uuid`                             Yes Foreign key to
                                                              `profiles(id)` with
                                                              `ON DELETE CASCADE`

  `track_id`           `uuid`                             Yes Foreign key to
                                                              `tracks(id)` with
                                                              `ON DELETE CASCADE`

  `played_at`          `timestamptz`                      Yes Defaults to `now()`

  `listened_seconds`   `integer`                          Yes Defaults to `0`; must
                                                              be non-negative
  ---------------------------------------------------------------------------------

Each row represents a playback event, not a unique user-track
combination. Users may read and insert only their own history. Avoid
writing an event for every small player update; define a
meaningful-listen threshold in the player implementation.

  -----------------------------------------------------------------------
  Resource          Anonymous visitor Authenticated     Trusted catalog
                                      user              workflow
  ----------------- ----------------- ----------------- -----------------

                    intentionally                       
                    exposed                             

  Track sources     Read only if      Read according to Create/update
                    intentionally     app rules         
                    exposed                             

  Own profile       No access         Read/update own   Maintenance as
                                                        needed

  Playlists         No access in MVP  Own playlists     Controlled
                                      only              maintenance

  Playlist          No access in MVP  Mutate own        Controlled
  membership                          playlists only    maintenance

  Likes             No access         Own likes only    No routine access
                                                        required

  Listening history No access         Own history only  No routine access

RLS is part of the design. Table grants and RLS policies must both be
configured. Elevated Supabase credentials must never be exposed to the
browser because they can bypass RLS.

## 7. Integrity constraints

The SQL migration should include: - Primary keys and foreign keys with
deliberate delete behavior. - Unique constraints for usernames, stable
provider references, playlist membership, playlist positions, and
likes. - Checks for non-empty names/titles, positive durations when
present, positive playlist positions, non-negative listened seconds, and
valid playback modes. - Database-level enforcement that an album and its
track have the same primary artist. - Indexes on commonly queried
foreign keys and access paths. - `updated_at` triggers for tables with
`updated_at`. - RLS policies for user-owned data. - Controlled catalog
writes so untrusted browser clients cannot arbitrarily modify catalog
records or source references.

## 8. Index plan

  --------------------------------------------------------------------------------
  Table                   Index / constraint               Query supported
  ----------------------- -------------------------------- -----------------------
  `profiles`              Unique `username` index          Username lookup

  `albums`                `artist_id`                      Albums by artist

  `tracks`                `artist_id`                      Tracks by artist

  `tracks`                `album_id`                       Tracks by album

  `track_sources`         `track_id`                       Sources for a track

  `track_sources`         Unique                           Provider lookup and
                          `(provider, provider_item_id)`   deduplication
                          where ID exists                  

  `playlists`             `(owner_id, updated_at DESC)`    User's playlists

  `playlist_tracks`       Primary key                      Playlist membership
                          `(playlist_id, track_id)`        

  `playlist_tracks`       Unique `(playlist_id, position)` Ordered playlist
                                                           retrieval

  `playlist_tracks`       `track_id`                       Playlists containing a
                                                           track

  `likes`                 Primary key                      User's liked tracks
                          `(user_id, track_id)`            

  `likes`                 `track_id`                       Track likes
                                                           lookup/count

  `listening_history`     `(user_id, played_at DESC)`      Recent listening
                                                           history

  `listening_history`     `track_id`                       Track history lookup
  --------------------------------------------------------------------------------

Add indexes for known queries and constraints rather than indexing every
column. Extra indexes consume storage and can slow writes.

## 9. Offline downloads and PWA storage

Offline data is device-local and is not stored in the canonical
PostgreSQL catalog.

  -----------------------------------------------------------------------
  Storage                             Data
  ----------------------------------- -----------------------------------
  IndexedDB                           Downloaded audio blobs, local
                                      download records, and cached track
                                      metadata

  Service Worker / Cache Storage      App shell, static assets, and
                                      selected cacheable resources

  PostgreSQL                          Canonical metadata, provider
                                      references, playlists, likes, and
                                      listening history
  -----------------------------------------------------------------------

A local download record should reference the canonical track ID and
include device-local state such as download status, file size, format,
and last validation time. This record belongs in IndexedDB for the MVP.

A future server-side downloads table is only needed for cross-device
preferences, synchronization, or download-management history. It cannot
replace the actual local audio file.

External provider embeds do not automatically work offline. Offline
playback requires a local copy obtained through a supported download
mechanism or a user-supplied file that may be stored and played locally.

## 10. Deliberately deferred scope

The initial schema does not implement: - Multiple credited artists per
track or album. - Collaborative playlists or public playlist sharing. -
Artist upload dashboards and contributor roles. - Licensing contracts or
rights-management workflows. - Audio transcoding variants or owned
media-object storage. - Recommendations and analytics rollups. -
Cross-device download synchronization. - Provider-specific
authentication tokens or subscription entitlements.

These can be added through later migrations when needed.

## 11. Phase 2.1 acceptance criteria

-   [ ] Supabase Auth remains the identity source.
-   [ ] All nine application tables are defined.
-   [ ] Artists, albums, and tracks remain separate entities.
-   [ ] A track can have multiple provider sources.
-   [ ] Singles can exist without an album.
-   [ ] Album and track primary artists must match.
-   [ ] `playlist_tracks` preserves membership and ordering.
-   [ ] User-owned data has explicit ownership rules.
-   [ ] RLS, grants, constraints, and indexes are specified.
-   [ ] Offline audio is stored locally rather than in PostgreSQL.
-   [ ] Provider playback and download capabilities are not assumed to
    be interchangeable.
